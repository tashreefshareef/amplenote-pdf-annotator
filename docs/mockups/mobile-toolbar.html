Mobile: what the toolbar costs, and three ways to spend less

Everything below is drawn at a real 358px note width — the figure measured on the device — with the viewer's own CSS and its @media (pointer: coarse) sizing applied, so the button heights are the ones your thumb actually gets. The box height is width / data-aspect-ratio and nothing else (api-notes.md §12), so every pixel the bar takes is a pixel of PDF you lose.

What shipped is option 2's shape, not option 1. One row went in first; the thumbnails button and the height toggle were then wanted on the bar rather than inside the menu, and neither fits a single row beside the pager and the four colours. Row 1 is thumbnails, the pager, then the height toggle and ⋮ at the right edge; row 2 is shape and colour. The shape group came back to the bar with them, so only the zoom stepper and the highlights list are left in the menu.

What a taller box would add on top

Independent of the layout: data-aspect-ratio 0.55 instead of 1.0 makes the same viewer 622px on this phone. It is written into the note markup, so the same viewer is that tall on desktop too — that is the whole trade, and it is why this is a control rather than a default.
