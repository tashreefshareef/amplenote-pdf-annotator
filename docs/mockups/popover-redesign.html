Highlight popover — redesign options

Every card below is drawn at 1:1 with the viewer's real tokens, swatch sizes and icons. Click things — the swatches, the shape buttons and the + are live.

What is wrong today

The card is a single wrapping flex row holding three different kinds of thing — a full-width shape row, eleven 20px circles, and four text buttons — inside a max-width: 320px box whose used width is measured at open time. So the wrap point moves: the same highlight gets 10 + 1 swatches or 11, and "Add note" lands on a different line. Nothing about the popover's content changed between these two.

279px — the 11th colour drops, and the buttons shuffle up beside it
296px — 17px wider and the same card reads completely differently

18 targets in one card (3 shapes + 11 colours + 4 actions) is the other half of "too busy" — every option below cuts that count and pins the width so the layout is decided at design time, not at open time.

Option A — two rows, fixed width · recommended

Row 1 answers "what should this mark look like": shape, then the four toolbar colours plus a + that opens the rest in place. Row 2 is what you can do with it, with "Add note" keeping its label because it is the suggested next step and the other three riding as icons. 9 visible targets, 252px, two rows always. Shipped at 270 × 91 — the real buttons carry the 1px transparent border .pdfa-btn keeps, which these mockup buttons do not, so the card measures 18px wider in the viewer than it does here.

Resting state — 252 × 93
After + — the seven colours the strip cannot already reach, as a fixed 7-column row
A mark that already has a note, wearing a non-toolbar colour

What + should contain

The drawer holds the catalogue minus whatever the strip is already showing — no colour appears twice in one card, and 7 fit on a single row, so the expanded card is 125px tall instead of 153. The alternative is to keep all eleven and dim the four, which is the vocabulary the palette picker already speaks (.pdfa-taken, styles.js) and which fixes every colour at a permanent position — worth it only if you think people will build muscle memory for where "mint" lives.

Seven, no repeats — 252 × 125 · recommended
All eleven, the strip's four dimmed — 252 × 153
The off-toolbar case: orchid holds the strip's 4th seat, so the drawer hands back blue in its place

Wins: one shape click preserved · colours never re-wrap · height never changes with the mark. Costs: Copy / Send / Remove lose their labels (tooltips + aria-labels carry them).

Option B — one row plus an overflow

The whole card is a single 214px strip: four colours, +, a divider, the note button, and a ⋮ holding shape, Copy, Send to note and Remove. This is the smallest card that still puts colour one click away.

Resting — 214 × 44
After + — the strip stays, the drawer opens under it
What ⋮ holds

Wins: tiny, covers almost no text, one shape of card in every context. Costs: changing a mark's shape becomes two clicks, and Remove is hidden behind a menu — worth measuring against how often you restyle.

Option C — colours only, everything else on ⋮

The most aggressive read of "compact": the card is a colour picker with an escape hatch. Same idea as the fast-path popover you already show on a fresh selection, so a mark's card and a selection's card finally look like the same object.

Resting — 178 × 44
Windows never lets you see the whole disk. You get a drive letter, a filesystem and a volume label. None of that depends on the shape of the hardware underneath. A folder cannot do this.
In place, over a highlight — how much text each card hides is the real test

Wins: smallest footprint, one consistent card everywhere. Costs: "Add note" — the thing the spec wants offered the moment a highlight is made — is no longer visible without opening a menu.
